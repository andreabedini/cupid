Building and Installing Hugs from Source
========================================

Hugs builds with meson on x86-64 and ARM64 machines running a current
Linux, macOS, Windows or BSD.  Windows builds are configured for but not
yet verified; see win32.txt.

Requirements:

    a C compiler (gcc or clang; the sources are standard C23)
    meson 1.1 or later, and ninja
    python3 (meson needs it anyway; the library build script uses it too)
    optionally readline or libedit, for command-line editing
    optionally bison, only if you change src/parser.y
    optionally hp2ps, to view heap profiles

Short version:

    meson setup build
    ninja -C build
    ninja -C build install

    hugs $(dirname $(command -v hugs))/../lib/hugs/demos/Say
    putStr (say "  /Hugs")
    :quit

Long version:

 1) Configure

        meson setup build --prefix=/usr/local

    Binaries go in $prefix/bin, the libraries in $prefix/lib/hugs (or
    lib64 on distributions that use it), the manual page in
    $prefix/share/man.  The library directory can be moved with
    -Dhugsdir=DIR.

    Options are set with -Dname=value on the meson setup command line,
    or later with meson configure.  "meson configure build" lists them
    with their current values.  The Hugs-specific ones are:

        readline                 auto/enabled/disabled: command-line
                                 editing with readline or libedit
        char-encoding            utf8 (default), locale or none: the
                                 encoding used for character I/O
        libraries                build the Haskell libraries (default
                                 true; needs a POSIX shell)
        profiling                heap profiler; statistics go to
                                 profile.hp, viewable with hp2ps
        timer                    time every evaluation (for
                                 benchmarking Hugs itself)
        debug-code, tag-checks, stack-dumps, internal-prims
                                 for debugging Hugs
        path-canonicalization    convert file names to absolute form
        small-banner             one-line startup banner
        explain-instance-resolution
                                 enable the :xplain command
        dont-panic               leave fatal signals to the debugger

    There is no configure-style probing of the system.  The facts about
    the supported targets are written down in src/sysdeps.h, the
    operating system and architecture names in the generated
    src/platform.h, and the mapping of C types to Haskell types and the
    errno and signal constants for the base library are computed at
    build time by libraries/tools/mksysconfig.c.

 2) Build

        ninja -C build

    This compiles hugs, runhugs and ffihugs, then builds the Haskell
    libraries into build/libraries/hugsdir.  The libraries under
    libraries/ are plain Haskell that Hugs owns; building them means
    copying them, generating the platform-dependent module
    Hugs.SysConfig and header HsBaseConfig.h with
    libraries/tools/mksysconfig, and running ffihugs over the modules
    with foreign imports (see libraries/tools/build-libraries).  The
    source tree is not written to.

    You can run Hugs in place:

        HUGSDIR=build/libraries/hugsdir build/src/hugs
        -- Try 1+2, [1..], etc.  Use ":quit" to exit

    or a script:

        build/src/runhugs -P'build/libraries/hugsdir/packages/*' Main.hs

 3) Install

        ninja -C build install

    DESTDIR is honoured for staged installs.

    Try a few simple tests:

        /usr/local/bin/hugs
        [1..10]
        :quit

        cat > echo <<EOF
        #! /usr/local/bin/runhugs +l

        > module Main(main) where
        > import System(getArgs)
        >
        > main = do { args <- getArgs; putStrLn (unwords args) }
        EOF
        chmod 755 echo
        ./echo Hello World

 4) Static analysis

    With a .clang-tidy file at the top of the tree, meson provides

        ninja -C build clang-tidy

    which runs the curated set of checks over the C sources.  Findings
    are reviewed by hand, never auto-fixed.

Preprocessing Haskell sources
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Hugs can run source files through a preprocessor before compiling them.
Use the "-F" option to name one, for example ":set -F'cpp -P'".  The
import chasing mechanism does not notice #includes, so you must :load
(not :reload) after changing an included file, and Hugs ignores
{-# LINE #-} pragmas, so error messages refer to the preprocessed line
numbers.
